LYHT UI is a plain-CSS system built around design tokens — one set of variables drives every card, button, and chart on this page, light or dark. No build step, no components to import. Just classes.

This is the whole idea

Move one token, watch everything follow

Every color on this page — the dashboard above, the buttons below, the badges in the table — reads from five CSS variables. Drag a swatch and the entire page repaints, because nothing here hardcodes a color; it all points back to :root.

--lyht-primary
links, primary buttons, active states
--lyht-success
positive stats, active badges
--lyht-warning
trialing / attention states
--lyht-danger
past-due / destructive actions

The kit

Buttons Badges & alerts Forms Nav & tabs Feedback Layout

Buttons

One base class, one modifier for intent, one for size. .btn.primary.lg reads exactly like it looks.

Badges & alerts

The same four semantic names — primary, success, warning, danger — repeat across badges, alerts, buttons, and progress bars. Learn the palette once.

Forms

Inputs, selects, and textareas are unstyled-tag-first — style a plain <input>, no wrapper class required.

Nav & tabs

Both share the same active-state language: current color, underline or background, no separate "active" theme to maintain.

Feedback

Modal, toast, dropdown, and tooltip all key off the same z-index scale, so nothing this page fires can end up stuck behind something else.

Layout primitives

.dash, .stack, and .split cover grid, vertical rhythm, and two-column layout — three primitives instead of memorizing flex utilities.
